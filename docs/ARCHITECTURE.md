# Архитектура СРЕДЫ

## Слои

```
src/
  app/                  UI (Next.js App Router): страницы, формы, серверные действия (app/actions), API-маршруты (app/api)
  components/           дизайн-система (ui/), макет (layout/), графики (charts/), элементы методики (sreda/)
  domain/               ЧИСТАЯ бизнес-логика без БД и фреймворка — тестируется модульно
    methodology/v1.ts   методика SERVICE 5D 5D-1.0: направления, критерии, вопросы, связи причин, решения
    ssi.ts              расчёт направлений и SSI, достоверность, ограничения
    analysis.ts         анализатор: противоречия, проблемы, статусы выводов, первопричины, рекомендации
    priority.ts         приоритизация P1–P4 (настраиваемые веса и пороги)
    tasks.ts            жизненный цикл задач, проверка доказательств, оценка результата замером
    anonymity.ts        k-анонимность, защита от вычитания, очистка текстов от контактов
    rbac.ts             права, роли, ограничения эксперта
    metrics.ts          бизнес-показатели → оценки критериев B1/B2
  server/               доступ к данным и сервисы приложения
    db/                 Prisma-клиент и tenantDb (принудительная изоляция компаний)
    auth/               Auth.js v5, пароли (argon2id), ограничение попыток входа
    ai/provider.ts      AI service layer: интерфейс провайдера, rules / openai-compatible
    services/           сценарии: организации, диагностика, анализ, план, задачи, команда, отчёты, помощник …
    context*.ts         контекст запроса: пользователь, компания, роль, права, область видимости
    storage.ts          файлы: S3-совместимое хранилище или локальный диск
    audit.ts, crypto.ts, logger.ts, errors.ts
prisma/                 схема, миграции, seed
tests/                  unit / integration / e2e
```

Правило зависимостей: `app → server → domain`. Домен ничего не импортирует из `server` и `app`. Страницы не обращаются к Prisma напрямую — только через сервисы (исключение: простые справочные выборки через `ctx.db`, которые изолированы тем же механизмом).

## Поток запроса

1. Страница вызывает `requireOrgContext(право)`, серверное действие — `actionContext(право)`.
2. Контекст загружает пользователя (с проверкой `sessionVersion` и блокировки), членство в компании, роль, итоговые права (`effectivePermissions`), область по точкам и `ctx.db = tenantDb(orgId)`.
3. Сервис проверяет право ещё раз (защита в глубину), валидирует вход (Zod) и работает с данными только через `ctx.db`.
4. Значимые действия пишутся в журнал аудита.

## Мультитенантность

Изоляция данных компаний построена в два уровня:

1. **Сервисы** проверяют права и область видимости.
2. **`tenantDb(orgId)`** — расширение Prisma. Во все операции с таблицами компании оно принудительно добавляет `organizationId`: в `where` для чтения, изменения и удаления, в `data` для создания. Попытку записи с чужим `organizationId` оно отклоняет. Даже если сервис ошибётся, запись другой компании нельзя ни прочитать, ни изменить по id — это подтверждают тесты `sprint1-foundation`.

Рекомендуемый третий уровень для продакшена — PostgreSQL Row-Level Security с `SET app.org_id` на соединение. Это задача следующего этапа.

## AI service layer

```
analysis.ts (детерминированный анализатор) ──► выводы, статусы, приоритеты, причины, рекомендации
                    │
                    ▼ (только при согласии компании и настроенном провайдере)
AIProvider.completeJson(schema)  ──► улучшенные формулировки (summary, текст рекомендаций)
```

- Провайдер выбирается переменной `AI_PROVIDER`: `rules` (без внешних вызовов) или `openai-compatible` (YandexGPT через совместимый шлюз, GigaChat-прокси, OpenAI, локальная модель).
- Во внешний провайдер уходят только агрегаты: коды и оценки критериев, заголовки проблем и причин. Тексты ответов, цитаты и имена не передаются.
- Ответ провайдера проверяется Zod-схемой. Провайдер не может добавлять проблемы, менять статусы, приоритеты и числа. При ошибке используется результат анализатора, а сбой фиксируется в ограничениях.
- Каждый анализ журналируется в `AIAnalysis`: версия методики, провайдер и модель, обезличенный вход, результат, ограничения, автор и дата.
- AI-помощник — единый координатор. Он определяет намерение и вызывает функцию-роль (Service Auditor, Customer Analyst, Performance Analyst, Team Analyst, Training Creator, Business Advisor). Ответ собирается из данных компании, с источниками и ограничениями.

## Модель данных (основное)

```
User ─< OrganizationMembership >─ Organization ─ Subscription
                │                      ├─< Role (права)          ├─< Location ─< Department ─< Employee
                │                      ├─< Invitation
                │                      ├─< Diagnostic ─< DiagnosticSource
                │                      │      ├─< Survey ─< SurveyQuestion ─ AssessmentCriterion ─ ServiceDimension
                │                      │      │      └─< SurveyResponse ─< SurveyAnswer      └─< SurveyInvite
                │                      │      ├─< Assessment (снимок расчёта)
                │                      │      ├─< AIAnalysis ─< AIRecommendation
                │                      │      ├─< Evidence
                │                      │      └─< Problem ─< ProblemCause
                │                      ├─< ImprovementPlan ─< Task ─< TaskChecklistItem / TaskComment / TaskEvidence ─ StoredFile
                │                      ├─< BusinessMetric (FACT / ESTIMATE / FORECAST)
                │                      ├─< Report ─ StoredFile
                │                      ├─< Notification, AuditLog
                │                      └─< TrainingCourse, Standard(Version), Checklist, CustomerFeedback, Complaint  (следующие этапы)
```

Полная схема с индексами и комментариями — в `prisma/schema.prisma`: 44 таблицы. Каждая бизнес-таблица содержит `organizationId` с индексом.

Удаление устроено так: бизнес-записи архивируются (`archivedAt`), а физически удаляются по политике хранения или при удалении компании (каскад от `Organization`).

## Ключевые архитектурные решения

| Решение | Почему | Компромисс |
| --- | --- | --- |
| Auth.js v5 (beta, версия закреплена) за модулем `server/auth` | Требование ТЗ; только v5 полноценно работает с App Router | Бета-версия; замена провайдера не затрагивает бизнес-логику |
| JWT-сессия + проверка пользователя в БД на каждом запросе | Credentials-провайдер Auth.js не поддерживает сессии в БД | Лишний запрос; зато блокировка и смена пароля действуют мгновенно (`sessionVersion`) |
| Prisma 7.10 stable вместо 8.0 RC | В продукт с ПДн не ставим релиз-кандидат | — |
| Детерминированный анализатор как основа AI | Воспроизводимость, объяснимость, работа без внешнего API и без передачи данных | Формулировки шаблонные; LLM подключается для текста |
| Server Actions + Zod вместо отдельного REST | Меньше кода, типобезопасность, CSRF-защита Next.js | Внешний API для интеграций — следующий этап |
| Снимки расчёта (`Assessment`) вместо пересчёта на лету | История и воспроизводимость при смене методики | Пересчёт создаёт новую запись |
