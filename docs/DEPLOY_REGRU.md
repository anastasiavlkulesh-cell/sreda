# Запуск СРЕДЫ на REG.RU

Итог: СРЕДА работает по адресу `https://ваш-домен` с автоматическим сертификатом HTTPS, ежедневной резервной копией базы и плановыми задачами. Время — около 30 минут, из них 5–10 минут уходит на сборку.

## 1. Закажите сервер

1. В личном кабинете REG.RU откройте раздел **«Облачные VPS»** и нажмите «Заказать сервер».
2. **Образ** — на вкладке «Приложения» выберите **Docker (Ubuntu 24.04)**. Подойдёт и чистая Ubuntu 22.04/24.04: скрипт установит Docker сам.
3. **Конфигурация** — для пилота минимум **2 vCPU, 4 ГБ RAM, 40 ГБ диска**. При 2 ГБ RAM первая сборка может не пройти.
4. Регион — Россия (требование 152-ФЗ для персональных данных).
5. После создания IP-адрес и пароль `root` придут письмом. Они также есть в карточке услуги на вкладке **«Доступы»**.

## 2. Направьте домен на сервер

Если домен уже есть на REG.RU: «Домены» → ваш домен → **«DNS-серверы и управление зоной»** → добавьте **A-запись**:

| Субдомен | Тип | Значение |
| --- | --- | --- |
| `@` (или `app` для app.вашдомен.ru) | A | IP-адрес сервера |

Записи DNS обновляются от 15 минут до нескольких часов. Без домена СРЕДА тоже запустится — по IP-адресу, но без HTTPS. Для работы с реальными компаниями домен с HTTPS обязателен.

## 3. Подключитесь к серверу

- **Mac или Linux:** откройте «Терминал» и введите `ssh root@IP-адрес`, затем пароль из письма.
- **Windows 10/11:** откройте PowerShell, команда та же.

При первом подключении ответьте `yes`. Символы пароля при вводе не отображаются — это нормально.

## 4. Установите СРЕДУ одной командой

Если репозиторий приватный, git запросит логин GitHub и токен доступа. Токен создаётся на GitHub: Settings → Developer settings → Personal access tokens, нужно право «Contents: Read». Можно и временно сделать репозиторий публичным.

```bash
git clone https://github.com/anastasiavlkulesh-cell/sreda.git /opt/sreda
cd /opt/sreda
bash deploy/install.sh
```

Скрипт задаст три вопроса:

1. **Домен** — например, `sreda.ru` или `app.sreda.ru`. Оставьте пустым, чтобы запустить по IP.
2. **SMTP для писем** — можно пропустить: приглашения тогда отправляются ссылкой вручную, уведомления остаются в приложении.
3. **Загрузить демо-данные?** — для знакомства ответьте `y`, для работы с реальными клиентами — `N`.

Дальше скрипт сам:

- сгенерирует секреты и сохранит их в `/opt/sreda/.env` (доступ только у root);
- откроет в firewall только порты SSH, 80 и 443;
- соберёт и запустит приложение, базу данных, HTTPS-прокси (Caddy) и резервное копирование;
- настроит плановые задачи: проверку просрочки задач (ежечасно) и политику хранения (ежедневно).

В конце скрипт покажет адрес. Откройте его и зарегистрируйтесь — первая учётная запись становится собственником компании.

> **Обязательно сохраните копию `/opt/sreda/.env` в надёжном месте** (менеджер паролей). Ключ `DATA_ENCRYPTION_KEY` нужен для расшифровки контактов. Без него восстановить их из резервной копии невозможно.

## 5. Почта для приглашений (по желанию)

Подойдёт почта на домене REG.RU, Яндекс 360 или Mail.ru для бизнеса. В `/opt/sreda/.env` укажите:

```
SMTP_URL="smtps://логин%40домен.ru:пароль@smtp.yandex.ru:465"
SMTP_FROM="СРЕДА <no-reply@домен.ru>"
```

Символ `@` в логине замените на `%40`. Затем примените настройки: `cd /opt/sreda && bash deploy/update.sh`.

## Обслуживание

| Задача | Команда (из `/opt/sreda`) |
| --- | --- |
| Обновить до новой версии из GitHub | `bash deploy/update.sh` |
| Посмотреть логи приложения | `docker compose -f deploy/docker-compose.prod.yml logs -f app` |
| Перезапустить | `docker compose -f deploy/docker-compose.prod.yml --env-file .env restart` |
| Список резервных копий | `docker compose -f deploy/docker-compose.prod.yml exec backup ls -lh /backups` |
| Восстановить из копии | `docker compose -f deploy/docker-compose.prod.yml exec backup pg_restore -h db -U sreda -d sreda --clean /backups/sreda-ГГГГ-ММ-ДД.dump` |

Резервные копии хранятся на том же сервере 14 дней. Для надёжности включите в REG.RU платные **снапшоты сервера** или копируйте `/backups` во внешнее хранилище.

## Если что-то пошло не так

- **Сайт не открывается по домену** — проверьте A-запись: команда `nslookup ваш-домен` должна показать IP сервера. Сертификат выпускается автоматически после того, как DNS обновится.
- **Ошибка при сборке** — пришлите вывод команды `docker compose -f deploy/docker-compose.prod.yml logs app | tail -50`.
- **Сборке не хватает памяти** — увеличьте RAM сервера до 4 ГБ в личном кабинете REG.RU.
