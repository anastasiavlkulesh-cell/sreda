# Запуск СРЕДЫ на Timeweb Cloud App Platform (без своего сервера)

Платформа сама собирает и запускает приложение из GitHub, выдаёт адрес с HTTPS и обновляет СРЕДУ при каждом изменении в репозитории. Работать в консоли сервера не нужно.

Что понадобится — три услуги Timeweb Cloud в одном регионе (Россия):

| Услуга | Зачем |
| --- | --- |
| **Облачная база данных PostgreSQL** | Все данные СРЕДЫ |
| **S3-хранилище** (бакет) | Файлы: доказательства выполнения задач, PDF-отчёты |
| **App Platform** (приложение) | Само приложение |

Время — около 40 минут, из них около 10 минут уходит на первую сборку.

---

## Шаг 1. Создайте секретные ключи (5 минут)

Нужны три случайные строки. Сгенерируйте их на своём компьютере и сохраните в менеджер паролей — **без ключа шифрования зашифрованные данные не восстановить**.

**Mac:** откройте «Терминал» и выполните команду три раза:
```bash
openssl rand -base64 32
```

**Windows:** откройте PowerShell и выполните три раза:
```powershell
$b = New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b)
```

Получатся три строки — назовём их **КЛЮЧ-1**, **КЛЮЧ-2** и **КЛЮЧ-3**.

## Шаг 2. Создайте базу данных

1. В панели Timeweb Cloud откройте **«Базы данных» → «Создать»**.
2. Выберите **PostgreSQL**, версию **16** (или новее) и регион в России. Для пилота хватит минимальной конфигурации.
3. Если панель предлагает **приватную сеть**, создайте её или выберите существующую. В эту же сеть позже добавите приложение.
4. Когда база будет готова, откройте её карточку и запишите: **хост** (приватный IP, если есть приватная сеть), **порт** (обычно 5432), **логин**, **пароль** и **имя базы**.

Соберите строку подключения:
```
postgresql://ЛОГИН:ПАРОЛЬ@ХОСТ:5432/ИМЯ_БАЗЫ
```
Если пароль содержит символы `@ : / ? #`, замените их: `@` → `%40`, `:` → `%3A`, `/` → `%2F`, `?` → `%3F`, `#` → `%23`. Если подключение идёт по публичному адресу и база требует SSL, добавьте в конец строки `?sslmode=require`.

## Шаг 3. Создайте S3-хранилище

1. Откройте **«S3-хранилище» → «Создать бакет»**. Тип — **приватный**, регион — Россия.
2. На вкладке **«Дашборд»** бакета скопируйте **S3 Access Key** и **S3 Secret Access Key**, а также запомните **имя бакета**.

Адрес хранилища Timeweb — `https://s3.twcstorage.ru`, регион — `ru-1`.

## Шаг 4. Создайте приложение

1. Откройте **App Platform → «Создать»** и выберите тип **Dockerfile**.
2. Подключите GitHub и выберите репозиторий **`anastasiavlkulesh-cell/sreda`**, ветку **`main`**. Автоматическое развёртывание оставьте включённым: каждое обновление в GitHub будет выкатываться само.
3. Регион — тот же, что у базы. Конфигурация — **не меньше 2 ГБ RAM**, лучше 4 ГБ.
4. Если базу вы создали в приватной сети, добавьте приложение в ту же сеть.
5. **Путь проверки состояния (health check)** — `/api/health`.
6. В разделе **переменных окружения** добавьте:

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | Строка подключения из шага 2 |
| `AUTH_SECRET` | КЛЮЧ-1 |
| `DATA_ENCRYPTION_KEY` | КЛЮЧ-2 |
| `CRON_SECRET` | КЛЮЧ-3 |
| `AUTH_TRUST_HOST` | `true` |
| `APP_URL` | Пока оставьте пустым — заполните на шаге 5 |
| `STORAGE_DRIVER` | `s3` |
| `S3_ENDPOINT` | `https://s3.twcstorage.ru` |
| `S3_REGION` | `ru-1` |
| `S3_BUCKET` | Имя бакета |
| `S3_ACCESS_KEY_ID` | S3 Access Key |
| `S3_SECRET_ACCESS_KEY` | S3 Secret Access Key |
| `INTERNAL_SCHEDULER` | `1` — встроенный планировщик: просрочка задач ежечасно, политика хранения ежедневно |
| `AI_PROVIDER` | `rules` |
| `SEED_DEMO` | `1` — загрузить демо-компанию для показа, `0` — для работы с реальными клиентами |
| `SMTP_URL` | Необязательно, для писем-приглашений: `smtps://логин%40домен.ru:пароль@smtp.yandex.ru:465` |
| `SMTP_FROM` | Необязательно: `СРЕДА <no-reply@домен.ru>` |

7. Нажмите **«Запустить»**. На вкладке логов будет видно, как идёт сборка (около 10 минут), затем строки «Применяю миграции базы данных…» и запуск сервера.

## Шаг 5. Адрес и домен

1. На вкладке **«Дашборд»** приложения появится технический адрес вида `https://….twc1.net`.
2. Впишите этот адрес (с `https://`) в переменную **`APP_URL`** и сохраните — приложение перезапустится. Этот адрес используется в ссылках на анкеты и приглашения.
3. Свой домен (например, `app.sreda.ru`) подключается в настройках приложения, раздел **«Домены»**. У регистратора домена добавьте DNS-запись, которую покажет Timeweb. После подключения поменяйте `APP_URL` на новый адрес.

## Шаг 6. Вход

- Если включили `SEED_DEMO=1`: войдите как `demo@sreda.local` / `DemoSreda2026`. Учётные записи ролей (`employee@sreda.local` и другие) используют тот же пароль.
- Для работы с реальными клиентами поставьте `SEED_DEMO=0` и зарегистрируйтесь — первая учётная запись становится собственником компании.

> Демо-учётные записи с известным паролем на рабочем стенде с реальными клиентами держать нельзя. Для пилота создайте отдельное приложение и отдельную базу с `SEED_DEMO=0` — или новую базу для этого приложения.

## Обслуживание

| Задача | Как |
| --- | --- |
| Обновить СРЕДУ | Новые изменения в ветке `main` на GitHub выкатываются автоматически |
| Логи | App Platform → приложение → вкладка «Логи» |
| Резервные копии базы | Карточка базы данных → «Бэкапы» (включите автоматическое создание) |
| Перезапуск | App Platform → приложение → «Перезапустить» |

## Если что-то пошло не так

- **Сборка падает с нехваткой памяти** — увеличьте конфигурацию приложения до 4 ГБ RAM.
- **В логах ошибка подключения к базе** — проверьте `DATABASE_URL`: экранирование спецсимволов в пароле, приватную сеть (приложение и база должны быть в одной сети) или добавьте `?sslmode=require`.
- **Не загружаются файлы** — проверьте ключи S3 и имя бакета.
- **Ссылки на анкеты ведут не туда** — проверьте `APP_URL`.

Если ошибка остаётся непонятной, пришлите последние 50 строк логов.
