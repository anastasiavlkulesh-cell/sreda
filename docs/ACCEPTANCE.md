## Ручная проверка на пилоте

После `npm run db:seed` войдите под каждой ролью (пароль `DemoSreda2026`) и проверьте, что видно в меню и что открывается:

| Учётная запись | Ожидается |
| --- | --- |
| `demo@sreda.local` (собственник) | Всё, включая утверждение плана, права ролей, журнал аудита |
| `network-manager@sreda.local` | Диагностика и анализ, план (без утверждения), задачи, команда, показатели, отчёты, приглашения |
| `location-manager@sreda.local` | Только «Кофейня на Садовой»: проблемы, план, задачи, команда, аналитика пульс-опросов |
| `manager@sreda.local` | Анкета руководителя, план (просмотр), задачи, список сотрудников; без проблем и результатов опросов |
| `employee@sreda.local` | Только свои задачи и личные настройки уведомлений |
| `platform-expert@sreda.local` | Просмотр аналитики на 30 дней; без управления компанией и людьми |

## Известные ограничения MVP

- Docker-образ не собирался в среде разработки (нет Docker-демона).
- Реальный внешний LLM не подключался (нет ключа); слой протестирован на имитации API.
- E-mail и Telegram отправляются только при заданных `SMTP_URL` и `TELEGRAM_BOT_TOKEN`. Без них уведомления остаются в приложении, и это показано в настройках.
- Повторное заполнение по общей публичной ссылке ограничено cookie устройства. Строгий контроль дают индивидуальные ссылки.
